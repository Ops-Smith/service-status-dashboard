2. Lab Overview & Domain Architecture

We will deploy this full-stack web application on AWS using direct console workflows.

Frontend Domain (remoteops.online)

Points to CloudFront (delivering private S3 static assets).

Backend Subdomain (api.remoteops.online)

Points to the EC2 instance (running Node.js/Express via Nginx reverse proxy).

Internet ──► Route 53 (DNS / Domain) ├── remoteops.online ─────► CloudFront (HTTPS + CDN) ──(OAC Access)──► S3 (HTML/CSS/JS Private Bucket) └── api.remoteops.online ─► EC2 (Node.js Backend) ACM Certificates ──► Applied to CloudFront & EC2

3. Learning Objectives

By completing this lab, you should understand how to:

Register & manage domain (remoteops.online) and hosted zones in Route 53.
Create private S3 bucket and upload static assets via AWS Console.
Secure S3 content delivery using CloudFront Origin Access Control (OAC).
Request & validate SSL/TLS certificates via AWS Certificate Manager (ACM).
Configure DNS A-records & Alias records in Route 53 for root & subdomains.
Launch and configure an Ubuntu EC2 compute instance.
Deploy Node.js/Express API (server.js) and run server backend.
Set up Nginx reverse proxy for internal Node.js backend processes.
Configure CORS between remoteops.online and api.remoteops.online.

4. Prerequisites

AWS Account

Permissions to create Route 53 records, S3 buckets, CloudFront distributions, ACM certificates, and EC2 instances.

Domain Name

remoteops.online configured in Route 53.

Local Codebase

Light frontend (index.html, script.js, style.css) and backend (server.js).

5. Step 1 — Route 53 Hosted Zone Setup

1

Open the AWS Console → Navigate to Route 53.

2

Click Hosted zones → Create hosted zone.

3

Enter remoteops.online and choose Public hosted zone.

4

Note the generated Name Servers (NS) and update them at your domain registrar so Route 53 becomes authoritative for remoteops.online.

6. Step 2 — Create Private S3 Bucket & Upload Frontend (Console Method)

1. Navigate to S3 → Click Create bucket.

2. Name the bucket (e.g., remoteops-online-frontend) and select Region.

3. Ensure Block all public access remains ENABLED (bucket stays private).

4. Click Create bucket.

5. Open newly created bucket → Click Upload.

6. Drag and drop index.html, script.js, and style.css directly into UI.

7. Click Upload.

7. Step 3 — Request ACM Certificate for CloudFront

Crucial: Switch AWS region to us-east-1 (N. Virginia) (CloudFront requires ACM certs in us-east-1).

• Navigate to Certificate Manager (ACM).

• Click Request public certificate.

• Enter domain names:

remoteops.online | *.remoteops.online

• Select DNS validation.

• Click Create records in Route 53 to auto-generate CNAME records, wait until status is Issued.

8. Step 4 — Configure CloudFront & S3 Origin Access Control (OAC)

1. Navigate to CloudFront → Create distribution.
2. Select S3 bucket (remoteops-online-frontend) as Origin domain.
3. Under Origin access, select Origin Access Control settings (OAC) & create OAC.
4. Set Viewer protocol policy to Redirect HTTP to HTTPS.
5. Under Alternate domain name (CNAME), add remoteops.online.
6. Under Custom SSL certificate, select ACM certificate for remoteops.online.
7. Set Default root object to index.html and save.

S3 Permissions Policy (Copy from CloudFront banner):

{ "Version": "2012-10-17", "Statement": [ { "Sid": "AllowCloudFrontServicePrincipal", "Effect": "Allow", "Principal": { "Service": "cloudfront.amazonaws.com" }, "Action": "s3:GetObject", "Resource": "arn:aws:s3:::remoteops-online-frontend/*", "Condition": { "StringEquals": { "AWS:SourceArn": "arn:aws:cloudfront::ACCOUNT_ID:distribution/DIST_ID" } } } ] }

9. Step 5 — Configure Frontend Route 53 Record (remoteops.online)

1

Navigate to Route 53 → Hosted zones → Select remoteops.online.

2

Click Create record.

3

Leave Record name blank (or use @ for root domain).

4

Choose A Record.

5

Enable Alias toggle → Select Alias to CloudFront distribution.

6

Select your CloudFront distribution and click Create records.

10. Step 6 — Deploy Node.js Backend on EC2

1. Launch Ubuntu EC2 Instance
Security Group: SSH (22), HTTP (80), HTTPS (443)
# SSH into EC2 server instance ssh -i your-key.pem ubuntu@EC2_PUBLIC_IP # Install dependencies & Node.js sudo apt update && sudo apt upgrade -y sudo apt install -y curl git nginx curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - sudo apt install -y nodejs # Navigate to backend directory & install cd ~/backend npm install

2. Verify CORS in server.js & launch application:

const express = require("express"); const cors = require("cors"); const app = express(); app.use(cors({ origin: "https://remoteops.online" })); app.get("/api/health", (req, res) => { res.json({ message: "Backend is running successfully on EC2" }); }); app.listen(3000, () => console.log("Backend running on port 3000"));
node server.js

11. Step 7 — Configure Nginx Reverse Proxy

Create Nginx site configuration:

sudo nano /etc/nginx/sites-available/api.remoteops.online
server { listen 80; server_name api.remoteops.online; location / { proxy_pass http://127.0.0.1:3000; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; } }

Enable configuration and restart Nginx service:

sudo ln -s /etc/nginx/sites-available/api.remoteops.online /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl restart nginx

12. Step 8 — Configure Subdomain Route 53 Record (api.remoteops.online)

1

Navigate to Route 53 → Hosted zones → Select remoteops.online.

2

Click Create record.

3

Enter api as the Record name (resulting in api.remoteops.online).

4

Select A Record.

5

Enter the Public IP (or Elastic IP) of your EC2 instance.

6

Click Create records.

14. Advanced Step — Automated S3 Synchronization via AWS CLI

This section is optional for students who wish to automate future frontend updates instead of manually uploading files via the console UI.

Install and configure AWS CLI locally:

aws configure

Sync local frontend files directly to the S3 bucket:

aws s3 sync ./frontend s3://remoteops-online-frontend

Invalidate CloudFront cache to deploy changes immediately:

aws cloudfront create-invalidation --distribution-id YOUR_DISTRIBUTION_ID --paths "/*"
